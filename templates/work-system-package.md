# Work System Package

A Work System Package is the handoff container for one AI-assisted workflow.

It is not a new framework layer. It is the practical package that collects the key deliverables, live setup, and records in one predictable place.

## Core Package

```text
Work System Package
1. Work Map
2. System Blueprint
3. Workflow Playbook
4. Live System & Records
```

## 1. Work Map

Purpose: diagnosis.

Answers:

- What was happening before?
- Where was the workflow breaking?
- Why did we choose this workflow?
- What is the desired business improvement?

## 2. System Blueprint

Purpose: architecture.

Defines the six-part Work System:

- Workflow
- Context
- Skills
- Interface
- Control
- Feedback

This is where Context, Memory, Skills, Interface, Control, and Feedback are designed.

## 3. Workflow Playbook

Purpose: operating manual.

Defines how the team runs the workflow:

- Trigger
- Inputs
- Steps
- AI role
- Skills used
- Human role
- Review points
- Output
- Destination
- Quality checklist
- Success metric
- Review rhythm

This is where the output process and feedback behavior are explained.

## 4. Live System & Records

Purpose: the actual working layer and evidence trail.

Includes links or locations for:

- Live interface
- Approved examples
- Final outputs
- Feedback Scorecard
- 30-day review notes
- Memory updates
- Important decisions or changes

## Clean Rule

```text
Blueprint defines the system.
Playbook explains how to run it.
Live System & Records stores what actually happens.
```

## When To Split Files

Keep the package simple by default.

Only split Context Pack, Skill Cards, Control Rules, or Feedback Scorecard into separate files/docs when they become too large to manage inside the Blueprint, Playbook, or Live System & Records.
